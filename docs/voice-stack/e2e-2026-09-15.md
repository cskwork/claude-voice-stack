# Live voice E2E verification, 2026-09-15

All three backends passed the same Korean audio-to-file-to-audio scenario on
Apple Silicon macOS. This run used the live GLM-5.3-Flash endpoint at Z.ai,
Whisper small through MLX, Supertonic, the actual Gateway application, and the
installed authenticated coding agents. No router or backend responses were mocked.

## Scenario and evidence

The test sent a synthesized Korean recording through the Gateway Client audio
protocol: "작업 폴더에 있는 안내 파일을 읽고 그 지시대로 결과 파일을 만들어 주세요."
Each backend received an isolated temporary workspace containing an instruction
file with a unique token unknown to the voice request.

For each backend, the run established that:

1. Whisper produced a recognizable Korean transcript.
2. GLM called `spawn_thinking` and the Gateway started a real backend task.
3. The backend read the instructions, wrote the exact token and newline into
   `result.txt`, read it back, and returned the token in its completed task result.
4. A subsequent `announcement` transcript referenced that completed task. Its
   response ID matched the captured completion audio and `audio.done` event.
5. The recording was non-silent mono PCM16 at 24 kHz. A separate Whisper pass
   recognized a Korean completion message in each saved recording.
6. All test Gateways and the speech service were stopped after verification.

Backend duration measures the Gateway's task start-to-completion interval; audio
duration is the length of the generated recording, not end-to-end latency.

## Limits and follow-up

The input was a recording, and playback receipts were simulated. This does not
test physical microphones, speakers, acoustic echo cancellation, or a human
conversation. No approval requests occurred under these installed agent settings,
so approval-dialog interaction was not exercised. Cancellation and failure
recovery were not part of this successful-task scenario.

The Claude completion included the test token in its spoken-summary text, and
the output transcription did not reliably preserve technical identifiers.
Identifier pronunciation and shorter spoken summaries remain quality improvements;
they did not affect the verified files or task outcomes.

The run kept provider credentials out of repository files and logs. The temporary
credential file was removed after use. Public evidence intentionally omits the
raw agent transcripts, which can contain local settings and extension inventories.

## Repeat

Configure the voice router and authenticate each selected CLI, then run:

```bash
npm run test:voice-stack:e2e
```

For one backend or a separate configuration file, use:

```bash
npm run test:voice-stack:e2e -- --backends codex --config /path/to/router.env
```

The runner prints the artifact directory containing `results.json`, events,
input audio, output audio, and generated files. Use a fresh directory for each run.
